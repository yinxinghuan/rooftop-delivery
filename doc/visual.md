# Rooftop Delivery 视觉规范

## 1. Visual thesis

- **游戏与受众**：Crazy Games 桌面横屏访客版，英文界面，键盘为主、鼠标拖投为辅。
- **情绪承诺**：在一座可以辨认街区功能的黄昏模型城市里，把有重量的纸箱越过街谷送到屋顶。
- **一句话方向**：航空邮政色板下的程序化微缩屋顶，每条路线用建筑轮廓、窗光与专属设施讲清地点身份。
- **标志性瞬间**：风旗先翻向，纸箱沿新弹道飞过街谷，命中后压扁回弹并弹出小费。
- **必须具备**：六景可辨、纸箱可辨、风向可见、落点因果清楚。
- **避免**：同高紫色方块排阵、下载模型、照片纹理、通用霓虹玻璃 UI、只靠 HUD 表示风。

## 2. Composition and camera

- 设计画布固定为 1600×900，并等比适配 800×450 桌面短框。
- 相机维持现有出发屋顶后上方的 16:9 透视；前景为发件屋顶，中景为街谷与目标屋顶，远景楼群形成高低节奏。
- 目标圈、巡逻动物和飞行走廊是受保护区域；专属设施留在屋顶边缘，不遮挡目标。
- 专属设施的主体分布在左右街楼和后方楼群，形成整条街的氛围；落点屋顶不摆整排衣物、花园陈列、主招牌、整座玻璃棚或灯塔，只允许一个水箱/天线和既有风旗。
- HUD 固定在上沿，蓄力条固定在下沿；一次性提示位于上中部且不覆盖包裹和落点。
- 六个街区共享并锁定 `fa376ab` 已成立的空间：近处发件屋顶、4 世界单位的楼间视觉间隔、8 世界单位宽的街道、街对面收件屋顶，以及左右各 11 栋连续街楼。不得靠拉远目标楼或拆散街楼制造差异。场景身份改由建筑结构表达：仓库装卸门、住宅阳台与晾衣、低层庭院花箱、夜间招牌楼、屋顶玻璃棚、深夜港区灯塔。

## 3. Color

- 公共天空与邮政 UI 延续暮紫 `#5B5E8B`、纸白 `#FFF5DE`、珊瑚 `#F05D4E`、风青 `#0F7F78`、提示金 `#F2C14E`。
- 六场景使用独立强调色：depot 铁锈橙、laundry 天蓝、garden 叶绿、neon 青紫、glasshouse 冷蓝、beacon 金黄深海军。
- 六景同时切换天空渐变、雾色、半球光、主光、轮廓光、街道与窗光；禁止让公共紫灰背景重新覆盖场景身份。neon 使用深靛天空、青/粉窗光和成组可读的大字灯牌；beacon 保持最深天空，只让窗灯与灯塔成为高亮。
- neon 不使用暗色底板、方牌或矩形亮框。文字只保留四组管状描边字：近处左楼竖排 `NIGHT`；横排 `EXPRESS` 与它共用相机正视的 `z≈-1` 墙面平面，置于左下侧，保持逐字灯管描边与明显字距，七个字母不得被楼角裁掉；右楼为 `PARCEL` 加向街箭头，后楼为圆形灯管中的 `24H`。四组在同一张 800×450 中完整可读。实体灯管统一为约 `0.06` 半径的圆管，外层光晕保持柔和但不形成白色方框。近处左右分别只突出一个杯子和一个箭头；其余粉、青、琥珀、绿符号缩小，十字只作少量远景节奏。每栋朝街檐口仍使用一根覆盖完整墙宽的通长细圆管，街谷左右各一根通长细圆管连接两个屋顶；落点屋顶不承载招牌或符号灯。
- bullseye 用珊瑚色；副投递圈用纸白/风青并带不同中心标记，不能只靠颜色区分。

## 4. Typography

- 展示字使用 Lilita One；正文与按钮使用 Nunito；精确数字沿用清晰的粗体数字。
- 800×450 下正文不低于等比后的可读尺寸；英文提示保持两行以内，不缩成微字。

## 5. Shape, material, and lighting

- 建筑由 Box、Cylinder、Cone、Plane、Ring 等 Three.js 基础几何组成；屋顶轮廓保持硬边微缩模型语言。
- 所有楼体都要有按高度生成的楼层线、成组窗户和可见女儿墙；六景再分别叠加装卸门、阳台、庭院花箱、霓虹灯带、玻璃棚框架或港区竖向构件，不能退化为带白点的方块。
- 每景必须有水箱或天线，并有一项专属设施：depot 货箱/装卸牌、laundry 晾衣绳、garden 花箱、neon 霓虹招牌、glasshouse 玻璃棚、beacon 灯塔灯。
- 侧街设施遵循建筑附着逻辑：装卸门贴临街底层，晾衣连接顶层窗与屋沿，花箱位于屋顶和窗台，霓虹字牌贴侧楼高层立面，玻璃棚落在侧楼屋顶，灯塔坐落在后方左侧楼顶；禁止漂浮或集中堆在落点屋顶。
- 光照延续左上暖日光与右后风青轮廓光；玻璃仅使用低透明度材质，不叠 UI 式模糊。

## 6. Characters, environments, and assets

- 不下载模型或纹理；城市、包裹、目标、风旗、衣物和设施全部程序化生成。
- 包裹固定为纸箱比例，顶面与侧面同时可见十字胶带，正面保留纸质标签。
- 场景专属物件必须从当前相机和 800×450 尺寸仍能辨认，细节不能只在代码中存在。
- 夜间合约复用六个场景组，通过既有灯光与场景轮换表达加班时段，不生成新城市身份。

## 7. UI and icons

- HUD、面板、按钮继续使用纸张、邮政印章与深墨描边系统；不改七步教学与八项升级结构。
- 功能图标使用现有统一 SVG 描边/实心体系，禁止 Emoji。
- 新机制只复用一次性提示卡；风翻转时 HUD 风向和场景旗帜同步，提示不变成第八步教学。
- 按钮目标至少 44×44 CSS px，并具备 hover、pressed、focus、disabled 状态。

## 8. Motion and VFX

- 风向翻转：风标先在约 180ms 内转向，随后更新预测线与物理风值。
- 屋顶命中：纸箱在接触后短暂压到约 72% 高度、横向略扩，再以阻尼回弹到原比例；小费文字从接触点上浮。
- 易碎失误：箱体保留在落点短暂停顿，表面出现两到三条深色裂纹，再进入失误恢复。
- 易碎裂纹同时绘制在箱体朝向相机的正面与顶面；结果浮字下移到前景屋顶，不能盖住远端箱体。
- 坠街：包裹持续绕两个轴翻滚并向街面下落，直至离开相机可见范围后才结算隐藏。
- reduced-motion 下保留状态差异，降低压缩、旋转与粒子幅度。

## 9. References translated into principles

- 已过审游客版方向提供“桌面短框、强状态文案、快速首局”的结构原则；不复制其资产或布局。
- 现有 Rooftop Delivery 提供投掷手感、邮政色板和黄昏模型城；本轮只加强地点身份与结果反馈，不重写引擎。

## 10. Anti-patterns

- 不把六种场景做成同一楼体换色。
- 不让专属物件遮住投递圈或动物路线。
- 不把箱子做成无胶带、无标签的纯色方块。
- 不让副落点误读为第二个 bullseye。
- 不为夜间合约增加路线数量、广告、内购、账号或第七座城。

## 11. Vertical-slice acceptance

- **开始页**：可见有高低层次和窗光的 depot 城市。
- **中局**：HUD、风旗、纸箱标签/十字胶带与目标同时可读。
- **高反馈**：第 7 关裂箱或第 6/9/10 关风向翻转有明确前因后果。
- **完成/恢复**：小费浮字与既有结算保持同一视觉语言。
- **短框**：800×450 无裁切、无横向滚动、无关键物被 HUD/提示遮挡。
- **QA**：至少保存装扮中局、特殊机制、非 depot 场景三张 800×450 截图；P0/P1 修复后同状态复拍。
